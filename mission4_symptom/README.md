# DCC 2026 대학부 본선 — Mission 4 제출 규격

환자 증상 조기예측 챌린지의 추론 템플릿(`inference.py`)과 채점 스크립트(`score.py`) 안내입니다. 채점은 이 규격에 따라 진행되므로, 제출 전에 반드시 본인 환경에서 아래 명령이 오류 없이 완주하는지 확인해 주십시오.

**평가 대상은 서울 구급 데이터입니다.** 9개 증상 클래스가 구급 데이터의 증상 분포를 기준으로 선정되었고, 평가셋도 구급에서만 추출합니다. 구조·기타·화재 분류는 평가에 쓰이지 않으니 학습 데이터를 구성하실 때 참고하십시오.

## 파일

| 파일 | 설명 |
| :---- | :---- |
| `inference.py` | 추론 템플릿. `Predictor` 클래스만 작성하고 나머지는 수정하지 않습니다. |
| `score.py` | 채점 스크립트. 주최측이 쓰는 것과 동일한 채점식입니다. |

## 실행 명령

```bash
python inference.py --mission 4-1 \
    --audio_dir {wav folder} --label_dir {json folder} \
    --ckpt_path {checkpoint file} --output ./outputs/mission4-1.csv

python inference.py --mission 4-2 \
    --audio_dir {wav folder} --label_dir {json folder} \
    --ckpt_path {checkpoint file} --output ./outputs/mission4-2.csv
```

내부적으로 전처리, feature 추출, 모델 추론, 후처리를 몇 단계로 나누든 상관없습니다. 다만 미션별로 위 명령 **한 번**만 실행하면 결과 파일이 생성되어야 합니다.

`--audio_dir`는 wav 루트 폴더를 가리킵니다. `--device cpu|cuda`와 디버깅용 `--limit N`도 사용할 수 있습니다.

**wav 파일명 규칙** — 배포되는 원천데이터의 wav는 라벨 json과 같은 stem을 씁니다.

```
651e464d69a4f266f062680c_20220101.json  ←→  651e464d69a4f266f062680c_20220101.wav
```

라벨링데이터 안의 `audioPath`는 AI-hub 내부 경로라 배포 파일명과 다릅니다. 템플릿이 `audioPath` 직접 결합 → 파일명 재탐색 → 라벨 stem 재탐색 순으로 찾으니 폴더 구조는 자유롭게 두셔도 됩니다.

wav를 하나라도 찾지 못하면 템플릿이 **즉시 실패**합니다. 그대로 진행하면 해당 샘플이 채점에서 조용히 0점이 되기 때문입니다. 경로를 확인하시고, 의도한 것이라면 `--allow_missing_audio`를 붙이십시오.

데이터는 **로컬 디스크**에 두십시오. 네트워크 드라이브나 클라우드 동기화 폴더에 두면 오디오 로딩이 수십 배 느려집니다.

진행 상황은 터미널에 진행바로 표시됩니다. `tqdm`이 설치돼 있으면 진행바를, 없으면 간단한 텍스트를 쓰므로 **`tqdm`을 설치하지 않아도 동작에 지장이 없습니다.** 출력을 파일로 리다이렉션하면 진행 표시가 자동으로 꺼집니다.

## 작성해야 하는 부분

`inference.py` 안의 `Predictor` 클래스에 있는 네 개 메서드입니다. 4-1과 4-2는 같은 클래스를 쓰며 `self.mission` 값(`"4-1"` 또는 `"4-2"`)으로 분기합니다.

- `load_model(ckpt_path)` — 학습 완료된 가중치를 로드해 모델 객체를 반환합니다.
- `reset()` — 새 통화가 시작될 때마다 호출됩니다. 누적 상태를 초기화하십시오.
- `step(utt)` — 발화조각 하나를 추가로 받았을 때 호출됩니다.
  - **4-1**: 매번 증상 리스트를 반환합니다. 판단이 서지 않으면 빈 리스트 `[]`.
  - **4-2**: 더 들으려면 `None`, 중단하려면 증상 리스트를 반환합니다. 반환하는 순간 그 통화의 스트림이 끝나고 중단 시점이 기록됩니다.
- `finalize()` — 4-2에서 끝까지 중단하지 않은 경우에만 호출됩니다. 이때 조기판단력은 최소값 0.5가 됩니다.

`step`에 전달되는 `Utterance` 객체가 제공하는 정보는 다음이 전부입니다.

| 필드 | 내용 |
| :---- | :---- |
| `index` | 대화 내 0-based 발화 순번 |
| `utt_id` | 라벨링데이터의 발화 id |
| `start_ms`, `end_ms` | 통화 시작 기준 발화 구간(밀리초) |
| `speaker` | 0 = 119대원, 1 = 신고자 |
| `text` | 전사 텍스트 |
| `audio` | 해당 구간 파형. `np.float32`, 16kHz 모노, shape `(n_samples,)` |

원본 wav가 8kHz든 44.1kHz든 템플릿이 16kHz 모노 float32로 통일해 잘라 넘깁니다. 팀별 샘플링레이트 차이는 발생하지 않습니다.

## 제약

- **대화의 전체 길이를 입력으로 사용할 수 없습니다.** 총 발화조각 수, 총 통화 시간 모두 해당합니다. 템플릿은 발화조각을 한 개씩만 흘려보내므로 정상적인 경로로는 전체 길이를 알 수 없습니다. 원본 wav를 직접 다시 읽는 등의 우회는 실격 사유입니다.
- symptom은 아래 9개 클래스만 취급합니다. 그 밖의 문자열은 자동 제거됩니다.

  `고열` `구토` `두통` `복통` `어지러움` `열상` `오심` `전신쇠약` `호흡곤란`

- 9개 클래스로 필터링한 뒤 symptom이 빈 리스트가 되는 샘플은 학습과 평가 모두에서 제외됩니다. 평가셋은 주최측이 미리 걸러 배포하므로 여러분이 따로 처리하실 것은 없습니다. 정답이 들어 있는 폴더로 직접 돌리실 때는 템플릿이 같은 규칙으로 걸러냅니다.
- AI-hub 제공 데이터만 사용하고 외부 데이터를 추가하지 않습니다. 공개 오픈소스 사전학습 모델은 허용하나, 별도 개발이 없는 상용 AI API는 금지입니다.
- Validation 폴더 데이터는 학습에 사용할 수 없습니다.
- 샘플마다 라벨에 따라 다른 전처리를 적용하거나, 평가 데이터에서만 유리한 전처리를 넣을 수 없습니다.

## 출력 CSV 규격

증상이 여러 개면 세미콜론(`;`)으로 잇고, 예측이 없으면 빈 문자열로 둡니다. 순서와 중복은 템플릿이 정규화하므로 신경 쓰지 않아도 됩니다.

**Mission 4-1** — `mission4-1.csv`, 샘플당 발화조각 수만큼의 행

```csv
label_file,step,symptom
A.json,1,
A.json,2,두통
A.json,3,두통;구토
```

`step`은 1-based 누적 발화조각 수입니다. 누락된 순간은 0점 처리됩니다. 평가셋 규모에 따라 이 파일은 수십 MB에 이를 수 있습니다.

**Mission 4-2** — `mission4-2.csv`, 샘플당 1행

```csv
label_file,halt_step,symptom
A.json,2,두통
B.json,5,복통;구토
```

`halt_step`은 중단까지 입력받은 발화조각 수입니다. 범위를 벗어나면 전체 길이로 보정되어 조기판단력이 최소값 0.5가 됩니다.

## 채점식

**Mission 4-1** — 각 (샘플, 순간)마다 클래스별 이진 F1을 계산해 평균합니다. 단일 인스턴스이므로 정답과 예측이 일치하면 1.0, 한쪽만 있으면 0.0이며, **정답에도 예측에도 없는 클래스는 평균에서 제외**합니다. 순간 점수를 순간에 대해 평균해 샘플 점수를 얻고, 샘플 점수를 샘플에 대해 평균해 최종 점수로 삼습니다.

아무것도 예측하지 않는 전략은 이 방식에서 보상받지 못합니다. 정답 클래스가 FN으로 남아 0점이 되기 때문입니다.

**Mission 4-2** — 중단 순간 예측에 대한 전체 평가셋 Macro-F1에 샘플평균 조기판단력을 곱합니다.

```
성능 = Macro F1 × 평균 조기판단력
조기판단력 = 0.5 + 0.5 × (1 − max(중단까지 입력받은 발화조각 수, 5) ÷ 전체 발화조각 수)
```

- 처음 5개 발화조각 안에서 중단하면 5번째 조각에서 중단한 것과 같은 조기판단력을 받습니다. 인사말 단계에서 서둘러 중단해도 이득이 없습니다.
- 끝까지 듣고 중단해도 조기판단력은 0이 아니라 최소 0.5입니다.

Macro-F1은 전체 평가셋을 풀링해 클래스별 F1을 구한 뒤 평균하며, 정답과 예측 어디에도 등장하지 않은 클래스는 평균에서 제외합니다.

**최종 순위** — Mission 4-1 순위와 4-2 순위의 합이 작은 팀이 상위입니다. 동점이면 4-1 점수가 높은 팀이 앞섭니다.

## 자체 채점

정답 `symptom`이 들어 있는 라벨 폴더가 있으면 주최측과 동일한 방식으로 미리 채점해 볼 수 있습니다.

```bash
python score.py --mission 4-1 --pred ./outputs/mission4-1.csv \
    --label_dir {json folder} --audio_dir {wav folder}
python score.py --mission 4-2 --pred ./outputs/mission4-2.csv \
    --label_dir {json folder} --audio_dir {wav folder}
```

`--audio_dir`를 함께 주면 `inference.py`와 동일한 기준으로 평가 대상을 확정하므로, 두 스크립트가 처리한 건수가 일치하는지 확인할 수 있습니다.

경고 메시지가 출력되면 제출 전에 반드시 해결해 주십시오. 행 누락, 중복 행, 범위를 벗어난 `halt_step`, 9개 클래스 밖 문자열, 규격에 맞지 않는 헤더가 대표적입니다. 경고는 기본 15건까지만 화면에 나오니 전량을 보시려면 `--out_json`을 쓰십시오.

## 평가 무결성

평가셋은 배포 전에 익명화됩니다. 파일명과 발화 id는 새로 부여되고, `_id`, `recordId`, 원본 `audioPath`, 그리고 `symptom`을 포함한 라벨 필드는 모두 제거됩니다.

제출물은 점수 산출과 별개로 **무결성 감사**를 거칩니다. 심사위원단이 제출된 `inference.py`를 여러 조건에서 직접 실행해, 모델이 그 시점에 실제로 주어진 입력만으로 판단하고 있는지 확인합니다. 구체적인 검증 방식과 기준은 공개하지 않습니다.

정상적으로 학습한 모델이라면 감사에 걸릴 일이 없습니다. 반대로 평가 데이터의 정답을 사전에 확보해 이용하는 행위, 지정된 입력 외의 정보를 참조하는 행위는 감사에서 드러납니다.

감사 결과는 순위에 자동 반영되지 않습니다. 특이사항이 있으면 심사위원단이 소명 기회를 드리고, 학습 로그가 담긴 `.ipynb`와 가중치 파일, 발표 내용을 함께 검토해 판단합니다.

## 제출 파일

- `inference.py` (본 규격 준수)
- 학습 코드 파일 (학습 로그가 포함된 `.ipynb`)
- 학습 완료된 모델 가중치 파일 (`.pt`, `.pth` 또는 `.ckpt`)
- 모델 코드 파일 (`.py`)
- `requirements.txt`
- 결과 정리 PPT (데이터 분석, 모델 설명, 결과 분석, 사회안전 시사점 포함)
