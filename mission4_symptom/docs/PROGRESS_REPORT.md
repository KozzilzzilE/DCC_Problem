## 시스템 구조

발화가 하나 들어올 때마다 아래를 한 번 돈다.

1. 지금까지 받은 발화의 전사를 공백으로 이어 붙인다. 입력은 전사뿐이다.
2. 누적 전사를 KLUE-RoBERTa-base(TAPT, 최대 512토큰)에 넣어 증상 9종의 확률을 낸다. 모델이 여러 개면 확률을 평균한다.
3. 학습 때 준 양성 가중치(pos_weight)만큼 로짓을 낮춰 확률을 실제 빈도에 맞춘다.
4. 4-1: 보정 확률과 학습 라벨의 증상 조합 분포로 "몇 개를 냈을 때 기대 순간 점수가 가장 큰지"를 계산해 그만큼 낸다 (`m4/decision.py` 의 maxent 규칙).
5. 4-2: 5번째 발화부터, 지금 답했을 때의 기대 순간 점수(증상 독립 가정으로 계산)가 0.52 이상이면 중단하고 보정 전 확률 0.5 이상인 증상(없으면 1개)을 낸다.

모델 가중치와 위 설정은 `.pt` 파일 하나에 담는다 (`m4/bundle.py`). 추론은 공식 템플릿에서 Predictor 만 구현한 `inference.py` → `m4/streaming.py` 다.
dev 200통화에서 공식 명령(`inference.py` → `score.py`)의 점수가 모의 채점과 일치했다 (4-1 0.5972, 4-2 0.5221).

## 전체 방안 재검토 (W001)

사용자 제안 세 가지(다른 계열 인코더, 증상별 확률 차이, 증상 1~2개 중심)를 출발점으로, 여섯 관점에서 dev 확률표로 실험하고 이득이 있다는 주장은 별도 검증(독립 재계산, 미래 정보 누출 점검, 다른 확률표에서의 방향 확인)을 거쳤다.
관점별 전체 결과는 `runs/W001_rethink/<관점>/REPORT.md` 에 있다. 시도한 방법은 80가지가 넘고, 검증을 통과한 것은 두 가지다.

### 사용자 제안에 대한 답

**1. 증상이 1~2개인 통화가 대부분이니 3개 이상은 덜 봐도 되지 않나** → 4-1 에서는 방향이 맞고, 4-2 에서는 틀렸다.

- 4-1 은 통화 평균이라 증상 1개 통화(67%)의 헛짚기를 줄이면 오른다. 다만 개수 상한을 2로 두는 것만으로는 +0.0015 로 seed 흔들림 안쪽이다. 같은 생각을 더 정교하게 구현한 것이 아래 "검증 통과 ①"이다.
- 4-2 는 증상별로 전체를 모아 F1 을 낸다. 3개 이상 통화는 통화의 7.9% 지만 양성 라벨의 17.4%, 중단 시점에 놓친 라벨의 26.9% 를 차지한다. 오심 양성의 44%, 구토 양성의 35% 가 이 통화에 있다.
- 4-2 중단 시점 예측을 2개로 막으면 −0.006, 1개로 막으면 −0.04 다(오심 F1 0.327 → 0.060). 3개 이상 통화에 학습 가중을 낮추거나 높이는 것도 한쪽 미션을 깎는다.

**2. 9종 확률이 증상마다 다르다는 점을 고려해야 한다** → 점검해 보니 지금 보정으로 충분했고, 증상별로 값을 따로 주는 방법은 이득이 없었다.

- pos_weight 만큼 로짓을 낮추는 보정만으로 9종 모두 평균 확률이 실제 양성률과 0.011 이내로 맞는다.
- 증상별 임계값, 증상별 중단 기준, 증상별 재보정은 dev 전체에서는 +0.004~0.006 이 나오지만 교차검증에서는 0 이하로 뒤집힌다.
- 공통 중단 기준 하나만으로 이미 증상별 중단 시점이 갈린다. 1위 증상이 고열·열상이면 중앙값 5번째, 전신쇠약이면 12번째에 끊는다.
- Macro-F1 의 바닥은 오심(중단 시점 F1 0.33)이다. 오심 양성 통화의 55% 는 끝까지 한 번도 확률 0.5 를 넘지 못해서, 임계값이 아니라 모델과 라벨 쪽 문제다.

**3. 계열이 다른 인코더** → E008 로 실행했고 채택하지 않는다 (위 실험 요약). 다른 계열이라 틀리는 곳이 조금 다르긴 하지만(오차 상관 0.958, seed 만 다르면 0.984) 단독 성능이 0.009 모자라 평균 이득이 0 이다. TF-IDF 같은 어휘 모델도 평균을 올리지 못했다.

### 검증을 통과한 방안 (①은 2026-11-12 코드에 반영, ②는 반영하지 않음)

**① 4-1 결정 규칙의 독립 가정을 실제 증상 조합 분포로 교체 (maxent)**

- 지금 규칙은 증상끼리 독립이라고 보고 계산해서 정답이 3~4개일 확률을 실제보다 크게 믿는다. 그 결과 평균 1.7개를 낸다(실제 1.42개).
- Training 라벨의 증상 조합 빈도(511칸)를 사전분포로 두고 다시 계산하면 dev 에서 고르는 값 없이 4-1 이 오른다.

| 확률표 | 현재 규칙 | maxent | 차이 [95% 구간] |
|---|---|---|---|
| E002 | 0.5447 | 0.5485 | +0.0038 [+0.0015, +0.0060] |
| E007 | 0.5453 | 0.5470 | +0.0017 [−0.0004, +0.0039] |
| 3개 평균 | 0.5484 | 0.5517 | +0.0033 [+0.0004, +0.0064] |

- 누출 없음. 확률표 6종 모두 같은 방향. 기대 이득은 4-1 +0.003 안팎이고 4-2 에는 쓰지 않는다(중단 신호로 쓰면 오히려 내려간다).
- **위험**: 증상 1개 통화에서 얻고 2개 이상 통화에서 잃는 교환이다. 평가셋의 증상 1개 통화 비율이 67% 에서 60% 로 내려가면 이득이 0 이 되고 55% 면 손해다. 평가셋 분포가 Training 과 같다는 가정에 기댄다.
- 같은 효과를 내는 다른 표현 세 가지(주변확률 일치 보정, 보정 온도 0.6, 보정 강도 λ 키우기)도 나왔지만 서로 겹치므로 하나만 써야 한다. 값을 고르지 않고 분포 변화에 가장 덜 민감한 maxent 가 맞다.

**② 4-2 학습형 중단 정책 (기대 점수 + β·δ̂ ≥ τ)**

- δ̂ 는 "지금 끊는 것과 조금 더 듣는 것의 효용 차이"를 맞히는 작은 GBM 이다. 대화 진행 특징(낱말, 화자, 시각)과 확률 계열 특징을 쓴다.
- 완전 중첩 교차검증에서 E002 +0.0045 [+0.0001, +0.0084], E007 +0.0031 [−0.0002, +0.0065], 3개 평균 +0.0047 [+0.0011, +0.0082]. 누출 없음, 다른 seed 모델로 옮겨도 유지된다.
- **한계**: 3개 평균에서는 τ 를 0.52 에서 0.50 으로 내리기만 해도 +0.0026 이 나오고, GBM 이 그 위에 보태는 것은 +0.0021 [−0.0015, +0.0057] 로 흔들림 수준이다. lightgbm 의존성과 가중치 포장 비용이 든다.

### 이득이 없거나 해로웠던 것

| 다른 멤버 | TF-IDF, 키워드 GBM, kNN, 음성 특징 쌓기 | 3개 평균을 올리지 못함 |

### 점수가 묶여 있는 이유

- 정답 증상이 통화에 한 번도 나오지 않는 통화가 35% 이고, 이 통화들이 4-1 손실의 47% 를 차지한다.
- 모델은 신고자가 증상을 말한 바로 그 발화에서 이미 93% 를 맞힌다. "말했는데 놓친" 것을 전부 고쳐도 4-1 +0.014, 4-2 +0.009 가 상한이다. 인코더를 더 좋게 만들어 얻을 몫이 이 정도다.
- 반대로 오답 추가를 전부 지우면 4-1 +0.113, 4-2 +0.082 다. 남은 레버는 "무엇을 낼 것인가"보다 "몇 개를 낼 것인가"다. 그런데 모델은 개수를 구분하지 못한다(정답 1개 통화에서 평균 1.61개, 4개 통화에서 1.95개).
