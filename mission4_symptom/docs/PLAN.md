# Mission 4 작업 계획

작성 2026-11-11. 브랜치 `mission4-streaming` (기준 `origin/mission4` b1aaea0).
실험 기록은 [EXPERIMENT_LOG.md](EXPERIMENT_LOG.md), 실험별 수치는 `runs/<실험 ID>/metrics_*.json` 에 남긴다.

## 문제 요약

예선 Mission 3(통화 전체 → 증상 9종)을 발화 단위 스트리밍으로 바꾼 문제다.

| | 4-1 누적입력 분류 | 4-2 중단 시스템 |
|---|---|---|
| 매 발화마다 | 증상 리스트를 반환 | `None`(더 듣기) 또는 리스트(중단) |
| 점수 | 순간 점수 = 맞힌 수 ÷ (정답 ∪ 예측 수) → 통화 평균 → 전체 평균 | 중단 시점 예측의 Macro-F1 × 평균 조기판단력 |
| 순위 | 4-1 순위 + 4-2 순위의 합 (동점이면 4-1 점수) | |

조기판단력 = 0.5 + 0.5 × (1 − max(중단 시점, 5) ÷ 전체 발화 수).

채점 기준은 공개된 `score.py` 로 본다. README 가 "주최측과 동일한 채점식"이라고 명시했고, README 의 설명도 score.py 와 같다.
출제 PDF 3쪽의 설명(class별 평균)과는 표현이 다르므로 주최측 확인이 남아 있다.

## 지킬 규칙

1. **Validation 은 학습에도, 값 고르기에도 쓰지 않는다.** 모델·임계값·중단 기준은 모두 Training 내부 dev(예선과 같은 분할, 2,920건)로 정한다.
   Validation 은 정해진 설정을 확인할 때만 돌리고, 돌릴 때마다 기록에 남긴다.
2. 예측은 그 순간까지 받은 발화에만 의존한다. 통화 전체 길이, 라벨 JSON 의 다른 필드, 원본 wav 재로딩은 쓰지 않는다.
3. `reset()` 으로 통화 사이 상태를 완전히 지우고, 같은 입력에는 같은 출력이 나오게 한다.
4. 실험 하나를 끝낼 때마다 기록(명령, 설정, 수치, 알게 된 것, 다음 할 일)을 먼저 쓰고 다음으로 넘어간다.

## 단계

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 0. 기반 | 통화 캐시, 누적 확률표, 모의 채점(주최측 score.py 와 값 일치 테스트) | 테스트 통과 |
| 1. 기준선 | 예선 모델(전체 통화로만 학습)을 누적 입력에 그대로 적용 | dev 4-1·4-2 점수 기록 |
| 2. 4-1 모델 | 누적 입력으로 학습(앞부분만 보고 맞히기), 입력 형식(화자 표시, 잘림 방향), 결정 규칙(빈 예측 방지, 개수 제한) | dev 4-1 이 기준선보다 유의하게 높음 |
| 3. 4-2 정책 | 확신도 기준, 안정 기준, 학습형 중단. 통화마다 다르게 끊기 | dev 4-2 가 고정 시점 중단보다 높음 |
| 4. 추론 구현 | `inference.py` Predictor, 속도(증분 인코딩·배치), 결정성, 감사 대비 테스트(통화 자르기·순서 섞기) | 템플릿 명령 두 개가 완주하고 모의 채점과 점수 일치 |
| 5. 제출물 | 최종 학습(Training 전체), 가중치 `.pt`, 학습 로그가 든 `.ipynb`, 모델 `.py`, requirements, Validation 확인 1회 | 빈 환경·오프라인에서 재현 |
| 6. 발표 자료 재료 | 데이터 분석 그림, 결과 분석, 사회안전 시사점(몇 초 일찍 판단하는지) | 요청이 있을 때 PPT 로 조립 |

## 진행 방식

- 학습은 GPU 한 장(RTX 5060 8GB)이라 한 번에 하나씩 돌린다. 여러 에이전트를 동시에 돌려도 학습은 빨라지지 않는다.
- 이 세션이 실험 순서와 기록을 맡는다. GPU 를 쓰지 않는 독립 작업(데이터 분석, 중단 정책 모의 실험, 추론 코드 점검)만 보조 에이전트로 나눈다.
- 제출 직전에는 추론 코드를 처음 보는 에이전트에게 맡겨 정보 누출·감사 위험을 따로 점검한다.

## 주최측·팀 확인이 필요한 것

1. 4-1 채점식: PDF 3쪽 설명과 score.py 중 무엇이 기준인가
2. 예선의 "임계값 0.5 고정" 규칙이 본선에도 적용되는가. 빈 예측을 막는 top-1 규칙과 4-2 중단 기준은 허용되는가
3. 제한 시간, 평가셋 규모 (채점은 GPU 로 본다)
4. 제출 기한과 발표 일정
