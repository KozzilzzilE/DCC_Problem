# 팀원 결과를 발전시키기 위한 다음 비교

상태: 설계 제안. 이 문서의 새 백본 비교 학습은 아직 실행하지 않았다. 현재 공개 요약의 개발 점수를 새 확인 결과로 바꾸어 쓰지 않는다.

## 첫 대상과 이유

KcELECTRA는 팀원 보고서에서 높은 수치를 보인 후보다. 다만 학습 데이터 출처와 평가 범위를 확인하기 전에는 해당 수치를 우수한 독립 성적으로 확정하지 않는다. [팀원 결과 검토](TEAM_RESULT_REVIEW.md)의 확인·미확인 구분을 먼저 따른다.

## 진행 순서

1. **원 실행의 데이터 출처부터 대조한다.** 팀원이 실제 사용한 캐시 생성 경로, 학습/평가 통화 ID 목록, 중복 검사, 실행 로그를 비공개 위치에서 확인한다. 파일 이름과 총개수만으로 누출 여부를 확정하지 않는다. 원 실행이 탐색 프로토타입이었다면 그렇게 기록한다.
2. **비교할 판정 규칙을 고정한다.** 증상 출력은 sigmoid 확률 `>= 0.50`, 빈 목록 유지, Top-1 강제 없음으로 비교한다. 임계값 탐색이나 maxent를 같은 주 비교에 섞지 않는다. 별도 보정이나 클래스 수 제한도 추가하지 않는다.
3. **같은 Training 내부 목록을 사용한다.** 기존에 동결된 10,000통화와 개발512통화를 사용하되 기존 보정용 통화와의 관계를 확인한다. 양 백본은 자신의 공개 사전학습 가중치에서 새 분류 head를 초기화한다. 이미 추가 학습한 RoBERTa와 새 KcELECTRA를 직접 비교해 백본 차이라고 주장하지 않는다.
4. **같은 시점과 원문을 보여준다.** 전체/초기/후기 prefix 목록·순서를 공유하고 미래 발화는 사용하지 않는다. 토크나이저가 달라 입력이 서로 다르게 잘릴 수 있으므로 두 토크나이저 모두512토큰 이내가 되는 공통 원문 구간을 생성·검증한다. 같은512토큰 제한이 같은 내용이라는 뜻은 아니다.
5. **작은 시간 측정을 먼저 한다.** T4 또는 L4 하나에서 초기 배치 시간·메모리·예상 전체 소요를 측정해 예산을 정한다. 큰 GPU를 자동 요청하거나 먼저 대규모 비교를 시작하지 않는다. 구체적 코드·모델 revision·학습량·중단 규칙을 동결한 다음 시작한다.
6. **seed42·43과 동일 학습 예산으로 대조한다.** 우선1epoch 고정 조건을 제안한다. 학습률·optimizer·손실 가중치·batch·학습 시점·최종epoch 선택 정책을 맞춘다. 서로 다른 백본의 사전학습 이력과 실제 토큰/연산량 차이는 따로 기록한다. 이 제안의 소규모 비교나 학습량 변경은 새 실행 ID로 남긴다.
7. **평균 점수 외의 오류도 확인한다.** 공개4-1 점수, seed별 차이, 통화 bootstrap CI, 단일/다중 점수, FN/FP, 빈 출력, 학습·추론 비용을 함께 비교한다. 전체 점수가 올라가도 다중 증상을 더 놓치는 경우는 별도 판단한다.
8. **개발 후 미사용 표본에서 확인한다.** 유망한 조건만 기존 평가 이력과 대조해 미사용 통화를 새로 등록한 뒤 확인한다. 과거에 일부 평가한 유보 분할 전체를 다시 미사용이라고 부르지 않는다. 공식 Validation은 모델·규칙을 고른 뒤의 허용된 최종 확인으로 구분한다.

## 사전 진입 기준 제안

실행 전에 고정할 제안 기준은 두 seed 모두4-1 개선, 두 seed 평균 차이+0.005 이상, 통화 단위2,000회 paired bootstrap 95% CI 하한>0, 각 seed의 다중 증상 점수 비악화다. 반복 사용한 Dev에서 이 기준을 통과해도 최종 채택이 아니라 미사용 표본 확인으로의 진입이다. 이 제안과 향후 실제 동결 프로토콜을 구분한다.

## 4-2와 팀원 방법의 재사용

학습형 중단 정책과 다른 계열 모델의 조합은 검토할 가치가 있다. 다만 입력은 현재 시점까지의 확률·텍스트·관측된 시간으로 제한한다. 전체 통화 길이·미래 증상은 추론 특징으로 쓸 수 없다. 학습형 정책은 Training의 통화 단위 OOF 예측으로 학습하고, 별도의 개발/확인 자료로 평가한다.

분류 임계값0.50과 중단 판단의 허용 규칙은 구분해 확인한다. 중단 정책의 실수 출력에 임의 변환을 붙여 숫자만0.50으로 보이게 만드는 방식은 규정 확인을 대신하지 못한다. 기존 maxent·Top-1·중단 기준 탐색은 유용한 연구 기록이지만 현재 확정된 제출 방식으로 표기하지 않는다.

## 보존

모든 조건×seed의 최종 모델, 마지막 optimizer/scaler/RNG·학습 위치 및 사용 시 scheduler 상태, tokenizer/config·revision, 소스·설정·명령·환경, 전 시점 확률·매핑·채점, 중단 이력과 무결성 목록을 비공개로 보관한다. 공개 저장소에는 집계 지표와 재현 방법만 올린다. 실제 학습을 시작하면 이 문서의 제안과 실행을 구분해 새 기록을 만든다.
