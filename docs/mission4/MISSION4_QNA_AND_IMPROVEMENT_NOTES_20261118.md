## 항목 1. 백본 모델 비교와 TAPT(119 도메인 빈칸 채우기 사전학습) 조건

### 1) 현재 상태
- **주력 백본 (`klue/roberta-base`):** 예선(Mission 3)에서 119 신고 전사 데이터로 도메인 추가 사전학습(`TAPT`, 빈칸 채우기 MLM 20 epoch)을 거친 뒤, 본선 증상 분류 파인튜닝(3 epoch)을 수행함(`SUBMISSION_README.md`).
- **비교 백본들:**
  - `mission4-streaming` 통제 비교([`EXPERIMENT_LOG.md`](../artifacts_private/team_branch_review_20261114/snapshots/mission4-streaming/mission4_symptom/docs/EXPERIMENT_LOG.md)): `KF-DeBERTa` (`E008`, `TAPT` 미적용, `4,992초` 약 `83분`, `maxent` 기준 `4-1 0.5354` vs `E002 0.5447`), `klue/roberta-large` (`E019`, `336M`, `TAPT` 미적용, `12,044초` 약 `3.3시간`, `maxent` 기준 `4-1 0.5451` vs `E002 0.5485`, 3개 평균 교체 `+0.0005`).
  - 초기 백본 브랜치(`KcELECTRA`, `KoELECTRA`, `KR-BERT`, `KoGPT2`, 초기 `roberta-large`): `TAPT` 미적용 상태이며, 일부 브랜치는 공식 `Validation` 경로 사용 또는 데이터 분할·캐시 출처가 통일되지 않아 직접 비교 보류 상태([`TEAM_RESULT_REVIEW.md`](team_branch_review_20261114/TEAM_RESULT_REVIEW.md)).

### 2) 문제점
- **비교 조건의 비대칭성:** `klue/roberta-base`에만 `TAPT`(119 도메인 사전학습)가 들어가 있고, `KF-DeBERTa`·`klue/roberta-large` 등 비교 백본들에는 `TAPT`가 적용되지 않은 채 파인튜닝만 수행됨.
- **발표 시 오해 위험:** 이 상태에서 *"동일 조건에서 모든 백본을 공정 비교한 결과 RoBERTa 아키텍처 자체가 가장 뛰어났다"* 고 주장하면, **`백본 구조/크기 효과`와 `TAPT 도메인 사전학습 효과`가 분리되지 않았다**는 심사위원의 반론을 받기 쉬움.

### 3) 개선할 사항
- **발표·보고서 서술 즉시 교정:**
  - 순수 백본 아키텍처 우월성으로 단정하지 말고, **"모든 후보 백본마다 20 epoch TAPT를 새로 돌리는 시간·GPU 비용 제약을 고려하여, 예선에서 이미 구축·검증된 `TAPT klue/roberta-base`와 `TAPT` 없는 대형/타 계열 백본(학습 시간 `2.4~3.3배` 소요)을 실용적 관점에서 대조했고, 비용 대비 성능이 가장 높은 `TAPT RoBERTa-base`에 후속 실험(손실함수·중단 정책)을 집중했다"** 고 정확히 구분해 서술함.
- **추가 실험 시 통제 기준 (시간·예산 여유 시 선택):**
  - 순수 백본 성능을 검증하려면 두 백본 모두 **공개 사전학습 가중치(No-TAPT)** 에서 출발해 동일 `fit 26,280` 분할과 `raw p >= 0.5` 기준으로 통제 비교([`NEXT_COMPARISON.md`](team_branch_review_20261114/NEXT_COMPARISON.md))하거나, 유망 이종 백본(`KcELECTRA` 등)에도 동일 `TAPT`를 적용한 뒤 비교해야 함.

## 항목 2. 동일 계열 다중 시드 앙상블(`ENS3`, `SJ 2-seed`)의 효율성과 근거 타당성

### 1) 현재 상태
- **기존 팀 앙상블 (`ENS3` = `E001 + E002 + E007`):** 끝까지 학습 모델 1개(`E001`) + 앞부분 균등 학습 모델 2개(`E002 seed 42`, `E007 seed 43`)를 균등 평균함. `E002`와 `E007`은 데이터·백본·하이퍼파라미터가 100% 동일하고 랜덤 시드(`42` vs `43`)만 다른 모델임(`origin/mission4-streaming` `runs/E002_prefix_uniform/run_config.json`, `runs/E007_prefix_uniform_s43/run_config.json`).
- **4-1 주력 후보 (`SJ 2-seed` = `SJ42 + SJ43`):** `SoftJaccard` 손실의 시드 `42`·`43` 모델을 평균함.
- **`Dev 2,920` (`raw p >= 0.5`, Top-1 없음, 4-2는 `C128_v1_nonempty`) 및 추론 비용 실측 비교:**
  - `E001 + E002` (2개) 대 `ENS3` (3개): `4-1` **`0.504316 → 0.506001` (`+0.001685`)**, `4-2` **`0.505164 → 0.507411` (`+0.002247`, `10,000`회 bootstrap `95% CI [-0.002022, +0.006612]`, `0` 포함)**.
  - `SJ42` (1개) 대 `SJ42 + SJ43` (2개): `4-1` **`0.526393` vs `0.526039` (`-0.000354`)**.
  - 추론 비용(`EXPERIMENT_LOG.md E010`, `SUBMISSION_README.md`): `Dev 200`통화 기준 1개(`4-1 44초 / 4-2 19초`) → 3개(`4-1 89초 / 4-2 38초`, 번들 `636 MiB`), `Validation 3,640`통화 기준 3개 `4-1 1,333초 / 4-2 461초`.

### 2) 문제점
- **연산 비용 대비 미미한 성능 향상:** 모델이 1개 늘 때마다 매 발화마다 RoBERTa 순전파 비용(추론 시간·VRAM·번들 용량)이 비례해 증가하지만, 동일 계열 모델 시드 하나(`E007` 또는 `SJ43`)를 추가해도 성능 차이는 `+0.002` 이하(4-2 신뢰구간 `0` 포함)이거나 오히려 소폭 낮음(`SJ42` 단독 `0.526393` > 2개 평균 `0.526039`).
- **설계 근거의 타당성 약점:** 추론 시간을 `1.5~2배` 더 쓰면서까지 시드만 다른 동일 모델을 2개씩 묶어야 할 명확한 통계적·구조적 근거가 부족해, 효율성 관점에서 "왜 굳이 모델을 2개 이상 쓰는지" 설명력이 떨어짐.

### 3) 개선할 사항
- **효율적 측면에서 최소 모델(1~2개) 대체 가능성 확인·검증:**
  - **4-1:** `SJ42` 1개(`0.526393`)와 `SJ42+SJ43` 2개(`0.526039`)의 실제 추론 시간(약 절반 단축) 및 시드 분산 차이를 비교해, 추가 비용 실익이 없다면 **단일 `SJ42` (`1개`) 채택 가능성**을 우선 검증함(`SJ43`은 손실함수 재현성 입증 증거로 활용).
  - **4-2:** `E001+E002` (끝1+앞1 = 2개, `0.505164`)와 `ENS3` (3개, `0.507411`) 사이에서 `E007` 1개 추가 비용(+50% 연산)의 실익을 점검하여, 효율 우선 시 **`E001+E002` (2개)** 경량 구성도 정식 비교 후보로 포함함(예: `4-1: SJ42 1개 + 4-2: E001+E002 2개` 구성 시 총 3멤버로 기존 `ENS3` 크기 내 유지 및 추론 시간 절감).
- **발표·보고서 논리 정리:**
  - 동일 구조의 시드 앙상블은 *"성능을 크게 올리는 핵심 기법"* 으로 포장하지 않고, **"시드 추가만으로는 개선이 정체(`+0.002` 이내, `CI` `0` 포함)된 반면, 손실함수 정렬(`SoftJaccard`, `+0.0200`)과 무누수 중단 브레이크(`C128_v1_nonempty`, `+0.0086`)는 추가 추론 비용 없이 본질적 개선을 달성했다"** 는 대비 근거로 위치시킴.
