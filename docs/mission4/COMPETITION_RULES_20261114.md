# DCC 본선(Mission 4) 대회 공식 공지·규정 및 평가 기준

기록일: 2026-11-14. 이후 모든 실험 설계·후처리·중단 정책·앙상블·제출 점검 및 발표 자료 작성 시 반드시 이 문서를 최우선으로 준수한다.

---

## 1. 공식 공지 원문 정리

### 1) Decision Threshold (결정 임계값) 규정
- 예선과 동일하게 **본선(미션 4-1, 4-2)에서도 Decision Threshold는 `0.5`로 고정**되며, **클래스별 임의 임계값 설정은 허용되지 않는다.**

### 2) 미션 4-2 중단 시점 판단 기준
- 증상 발생 여부를 판단하는 임계값과 동일하게, **해당 중단 판단 기준값 역시 `0.5`를 기준으로 설정하여 적용**해야 한다.
- **대화의 전체 길이(총 발화조각 수, 총 통화 시간)는 중단 시점 판단에 사용할 수 없다.**
- 중단 여부는 **해당 시점까지 제공된 정보만을 바탕으로** 결정해야 한다.

### 3) 검증 데이터 기반 파라미터 튜닝 및 앙상블 허용 범위
- **제공된 학습 데이터(Train)를 분할하여 구축한 자체 검증 데이터(Validation) 내에서 수행하는 모델 앙상블 가중치 탐색 및 하이퍼파라미터 튜닝은 모델 개발의 일환으로 허용**된다.
- 단, 위 **1·2번에서 명시한 최종 판정 및 기준값 `0.5` 고정 원칙은 반드시 준수**해야 한다.

## 2. 본선 평가 기준 안내

예선 심사 결과에서도 상위권 팀 간 정량적 성능 지표는 근소한 차이에 불과했으므로, 본 대회는 수치뿐 아니라 **과정의 논리성과 팀의 협업 역량**을 종합 평가한다.

1. **예선 결과 반영 (30%)**
2. **정량 평가**:
   - **(미션 4-1)** 환자의 증상 인식 정확도 *(공지 표기 F1-score; 공개 채점 코드 [score.py](../tools/full22k/score.py) 구현은 시점별 평균 Jaccard 점수)*
   - **(미션 4-2)** 조기판단력으로 보정한 환자의 증상 인식 정확도 (`Macro-F1 × 평균 조기판단력`)
3. **정성 평가 (과정 및 역량)**:
   - 성능 개선 과정과 결과 도출의 **논리적 타당성**
   - 팀원 간 미션 수행을 위한 **역할 배분의 적절성**
   - 팀이 수행한 미션 과정과 도출 결과에 대한 **팀 전체의 이해도**
   - 과제 수행 절차, 한계/문제점 극복 과정, 프레젠테이션 완성도 등 **발표의 논리적 전개 수준**

## 3. 작업 시 준수 체크리스트 (허용 vs 금지)

| 항목 | 규정 적합 여부 | 구체 적용 원칙 |
|---|---|---|
| 전역 임계값 조정 (`global_thresh != 0.5`, 예: `0.63`, `0.69`) | **금지 (제출 불가)** | 과거 `decision_calibration` / `full22k`의 `global_thresh_top1`은 내부 탐색 참고치로만 보존하며 제출에 사용하지 않는다. |
| 클래스별 임의 임계값 (`class_thresh`) 및 `maxent/expected` | **금지 (제출 불가)** | 증상별 서로 다른 임계값 또는 임의 기대점수 기반 개수 선택을 사용하지 않는다. |
| **증상 최종 판정 `p >= 0.5` 고정 (`unchanged_050`)** | **필수 허용 기준** | 모든 공식 비교·선정의 1차 기준 지표는 반드시 `raw probability >= 0.5` (Top-1 강제 출력 없음)로 평가한다. |
| 빈 예측 시 `Top-1 fallback` 강제 출력 | **보수적 제한 (미허용 간주 권장)** | 임계값 `0.5` 미만을 강제 출력하는 행위는 `0.5` 고정 원칙에 위배될 소지가 있으므로, 운영진의 명시적 서면 허용이 없는 한 제출 규칙으로 채택하지 않고 참고 지표로만 분리 보고한다. |
| 4-2 중단 시점 기준값 `0.70` / `0.80` / `0.90` 직접 사용 | **금지 (규정 수정 필요)** | 중단 판단 기준값 역시 **`0.5`를 기준**으로 설정해야 하므로, 기존 `c=0.70/0.80/0.90` 격자 탐색 결과는 규정 준수 버전으로 대체해야 한다. |
| **4-2 규정 준수 중단 설계 (`0.5` 기준)** | **허용 방향** | ① 누적 정보만으로 `p >= 0.5` 기반 연속 안정성/최소 발화 규칙 검증 ② 별도 **학습형 중단 분류기 `P(stop \| current_prefix_features) >= 0.5`**를 Train 내부 분할 OOF로 학습(기준값 `0.5`, 총 발화수·통화 시간 미래 정보 절대 금지). |
| **Train 자체 분할 기반 하이퍼파라미터 튜닝 & 앙상블 가중치 탐색** | **허용 (핵심 정공법)** | `cal1k` 등 Train 내부 자체 검증 분할을 이용해 학습률·스케줄·손실 설정·이종/동종 모델 확률 **앙상블 가중치(`w`)**를 탐색하되, 결합된 최종 확률에 반드시 **`>= 0.5`**를 적용한다. |

## 4. 기존 `full22k` 기준선(`b1_full22k_cosine_v1_20261114`) 규정 기준 재정렬

공식 공지 적용 시, `b1_full22k_cosine_v1_20261114`에서 **규정 100% 준수 기준(`raw p >= 0.5`, Top-1 없음)** 공식 성적은 다음과 같다([RESULT_REVIEW.md](full22k_20261114/RESULT_REVIEW.md)).

- **`dev512` (`unchanged_050`)**: Parent 단일 평균 `0.446236` → Full22k 단일 평균 **`0.464369`** (`+0.018133`, 4/4 게이트 통과) / 2-시드 앙상블 **`0.467813`**
- **`confirm_dev512` (`unchanged_050`)**: Parent 단일 평균 `0.481845` → Full22k 단일 평균 **`0.501201`** (`+0.019356`, 4/4 게이트 통과) / 2-시드 앙상블 **`0.505813`**
- **결론**: 임계값 튜닝·Top-1 없이 순수 `0.5` 고정 기준에서도 `22,509`통화 학습 확장이 **확실하게(+0.018~+0.019) 성능을 끌어올렸음**이 검증되었다.

## 5. 앞으로의 실험 및 발표 전략 (정량 + 정성 극대화)

1. **`0.5` 고정 기준에서의 정량 개선 정공법**:
   - 후처리 임계값 트릭 대신 **모델 확률 자체의 품질 향상**에 집중한다:
     - **Track 2 (`klue/roberta-large`, L4/T4 전용)** 학습 및 평가 (`raw >= 0.5` 중심)
     - **다른 계열 백본 (`KcELECTRA` 등 clean Train-only 재현 비교)** 추가 검토
     - **`cal1k` 등 Train 자체 검증 분할에서 `0.5` 기준을 직접 최적화하는 앙상블 가중치 결합** (`base + large + KcELECTRA` 확률 평균 뒤 `>= 0.5`)
     - **`0.5` 기준 미션 4-2 중단 시스템** 재설계 및 평가 (`p >= 0.5` 안정성 규칙 및 Train OOF 학습형 `stop_head >= 0.5`, 미래/전체 길이 미사용)
2. **정성 평가(발표·논리성·협업·이해도) 대비**:
   - 모든 실험의 **`가설 → 통제 비교 → 실패/보류 원인 분석 → 다음 가설 전환 → 최종 채택`** 흐름을 팀 전체가 설명 가능하게 일관된 논리로 연결한다([EXPERIMENT_RECORDING_STANDARD.md](EXPERIMENT_RECORDING_STANDARD.md)).
