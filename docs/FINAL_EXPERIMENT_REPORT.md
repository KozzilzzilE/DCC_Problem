## 1. 프로젝트 목표와 평가 규정

### 1.1 과제 정의와 입력 제약
- **목표**: 119 긴급 통화 음성 발화 구간만으로 화자 역할(상황실 접수요원 0 vs 신고자 1) 이진 분류.
- **입력 데이터**: JSON 라벨의 `startAt`과 `endAt`으로 지정된 단일 발화 음성 구간. 다른 발화의 음성을 이어 붙이거나 전체 통화 문맥을 입력으로 사용할 수 없다.
- **금지 사항**: 어휘, 프로토콜 문장, 대화 텍스트, 발화 순서(홀짝 여부) 등 추가 메타데이터를 모델 입력이나 분기 조건으로 사용하는 것은 엄격히 금지된다.
- **전처리 공정성**: 정답 라벨에 따른 차등 전처리를 금지하며, 동일한 전처리가 양 클래스와 학습/추론 전 과정에 동일하게 적용된다.
- **공식 평가지표**: **Accuracy (정확도)**가 주 지표이며, Macro F1과 클래스별 Recall을 보조 지표로 활용한다. 결정 임계값은 0.50으로 고정한다.

### 1.2 평가 모집단 및 28건 음원 누락 규명
- 검증 라벨 JSON 3,640개 파일의 총 발화 수는 111,947건이다.
- 전수 데이터 감사 결과, 1개 JSON 파일(`651e5494386c2a48273e4ed2_20220305.json`)에 대응하는 WAV 음성 파일이 원천 데이터셋 배포 시 누락되어 있음을 확인했다.
- 해당 파일의 28건 발화(상황실 15건, 신고자 13건)를 제외한 실제 유효 음향 평가 가능 모집단은 **111,919건**이다 (상황실 53,830건 / 48.10%, 신고자 58,089건 / 51.90%). 6절의 기존 가중치 전수 성적은 이 111,919건을 분모로 산출되었다. 초기 탐색 및 Training 내부 파일럿은 각각의 표본 수를 분모로 사용하며 신규 전수 평가 결과는 대기 중이다.
- 제출 CLI(`inference.py`)는 음원 누락 시에도 무음 처리 기반 fail-safe를 적용하여 111,947개 발화 행을 온전히 보존하거나, 유효 음원 목록에 따라 111,919행을 생성할 수 있도록 방어적으로 설계되었다.
- 학습 통화 29,142건과 검증 통화 3,640건 간의 통화 세션 ID 중복률은 0.0%로 분리 독립성이 검증되었다.

### 2.2 해석과 적용 범위의 한계
- 1.5초 대비 3.0초 zero 패딩(Pre-3)이 정확도 +1.01%p 향상을 보여 후속 모델의 기본 입력 길이로 채택되었다.
- **해석상의 한계**: 본 실험은 1.5초와 3.0초의 제한된 조건 비교이며, 모든 오디오 모델과 임의의 길이에 대한 전역 최적값을 증명한 것은 아니다.
- 발화 평균 길이가 2초대라는 점과 3초 윈도우 내 대부분의 유효 음성이 수용된다는 점을 고려한 실용적 선택이다.
- 이후 탐색된 ReDimNet과 ECAPA-TDNN은 모델 구조 특성에 맞추어 FFT 512 / hop 160(80-Mel)을 적용했다.

### 3.2 후보 아키텍처별 탐색 결과 및 세부 분석
1. **합성곱 / TDNN 계열**:
   - **ReDimNet2-B2**: 2D+1D 하이브리드 CNN과 Multi-Head Attention Pooling을 결합하여 2.57M의 극소 파라미터로 높은 표현력을 확보.
   - **ECAPA-TDNN**: 1D Res2Net 합성곱 블록과 Squeeze-and-Excitation, Attentive Statistics Pooling을 적용한 화자 임베딩 전문 모델 (5.80M 파라미터).
   - **AudioResNet-50**: 1채널 멜 스펙트로그램 입력을 수용하도록 수정한 2D ResNet-50 (23.50M 파라미터).
2. **사전학습 음성 트랜스포머 (Wav2Vec2)**:
   - Git d6cdee7 기록에서 `facebook/wav2vec2-base` 5에폭 완료 로그 확인 (38,267건 학습, 9,138건 검증, Accuracy 89.72%, Macro F1 0.8965, A100 GPU 배치 32 환경에서 총 27.08분 소요).
   - 동일 9,138건 집합에서 ResNet과 Wav2Vec2의 앙상블은 Accuracy 91.05%, Macro F1 0.9101을 기록하여 트랜스포머의 오류 보완 가능성을 입증했다.
   - 따라서 "트랜스포머가 전면 실패했다"는 서술은 사실과 다르며, 부분 집합 학습 및 앙상블에서 유효한 성적을 거두었다.
3. **스펙트로그램 트랜스포머 (로컬 SSAST_Tiny)**:
   - 로컬 `SSAST_Tiny` 구현(Patch Embedding + TransformerEncoder, 1.48M)을 테스트했다. 이는 공식 SSAST 사전학습 87M 모델과 다른 로컬 프로토타입 구현이다. 이 모델로 200통화 파일럿을 완료했다는 근거는 없다.
4. **기타 트랜스포머 후보 (HuBERT, WavLM)**:
   - HuBERT는 원격 가중치 다운로드 및 세션 타임아웃으로 보류되었으며, 자체 Conv fallback 모델이 존재했다.
   - 일부 프로토타입 셀에 남아 있던 메모리 수치(14GB대)는 실제 forward/backward 계측 로그가 없는 과거 프로토타입 셀의 미검증 출력이다.

### 4.2 Training 내부 200통화 파일럿과 다섯 가설의 검토 범위

기존 모델/앙상블 탐색 이후 수행한 후속 파일럿이다. 과거 모델 선정에 앞서 이 검증을 완료한 것처럼 서술하지 않는다. 아래 수치는 Windows 작업자가 전달한 `HYPOTHESIS_RESULTS` 및 `PREPROCESSING_PILOT_RESULT`의 기록이다. 이 저장소 검토에서 실제 음원/예측 배열을 재실행하지 않았다. Training 200통화의 6,075발화를 통화 단위 80:20으로 나누어 Train 4,913건, 내부 Dev 1,162건을 사용했다. 공식 Validation은 이 파일럿에 사용하지 않았다. 특징 표준화 계수는 Train에서만 계산했다. seed 43은 동일 표본/분할에서 초기화만 반복한 결과다.

파일럿 관찰 평균은 상황실/신고자 순서로 발화 길이 **1.77 / 2.14초**, RMS 프레임 표준편차 **0.0325 / 0.0406**, Centroid **866.4 / 1,043.5Hz**, ZCR **0.0874 / 0.1044**로 전달됐다. Centroid와 ZCR의 방향은 355건 초기 탐색 기록과 반대다. 이 표본 차이를 마이크 종류나 감정의 인과 효과로 단정하지 않는다. Centroid는 스펙트럼 무게중심이며 pitch 자체가 아니다. ZCR은 신호의 영교차 비율이며 마찰음 비율 자체가 아니다.

로지스틱 회귀의 전체 특징 모델 정확도는 72.98%이며 Centroid 소거 모델은 67.13%였다. Duration 소거의 `전체 - 소거` 차이는 -0.34%p [-0.80, 0.00]이다. 이 소거 실험은 Tiny CNN 또는 Frozen ResNet의 실험이 아니다.

|---|---|---|---|---|
| Tiny CNN, seed 42 | 63.25% | 72.38% (+9.12%p) | 70.48% (+7.23%p) | 내부 Dev, 3에포크 파일럿 |

CI는 Dev 통화 단위 500회 paired bootstrap으로 보고됐다. 0을 포함하는 CI는 이 조건에서 이득을 확인하지 못했다는 뜻이며, 동등성이나 효과 부재의 증명이 아니다. 심층 백본이 수작업 특징을 완전히 대체했다는 메커니즘도 입증하지 않았다. 여러 조건 탐색과 Dev 기반 epoch 선정의 불확실성은 별도로 남아 있다.

파일럿 ResNet은 일반 ImageNet 초기화, 80-Mel / FFT 512 / hop 160과 보조 특징 슬롯을 사용했다. 최종 AudioResNet의 128-Mel / FFT 2048 / hop 512 및 보존 가중치와 다른 조건이다. 보조 통계는 크롭·패딩 전 발화 전체에서 계산하므로 3초 Mel보다 더 긴 발화 정보를 포함할 수 있다. 최종 백본 전체의 효과로 직접 일반화하지 않는다.

다섯 질문에 대한 탐색 비교는 있었으나 모든 가설이 참으로 검증된 것은 아니다. ResNet Full FT의 1.5초 조건 및 최종 ReDimNet/ECAPA에서의 특징 결합 비교는 미완료다. 신규 추가 학습은 사전에 고정한 기본 3초 Mel을 사용하고, 향후 대조 실험은 Training 내부 Dev에서 수행한다.

## 8. 재현성 검증과 91.56% 결함 규명

### 8.1 초기 재현 91.56%의 결함 보고와 수정 후 기록

Windows 작업자는 AudioResNet의 GPU Mel 상대 dB 계산에서 무음 에너지 `ref`가 0이 되어 NaN이 발생한 1,180건을 발견하고, `ref = torch.clamp(ref, min=1e-10)`으로 수정했다고 보고했다. NaN 비교가 조용히 라벨 0으로 처리되는 것을 막기 위해 제출 코드에는 비정상 확률을 거부하는 검사를 유지한다. 이 NaN 건수/원인 분석 원배열은 로컬 검증 산출물이며 현재 Git 코드 검토에서 독립 재실행하지 않았다.

보존된 보고 수치에서 ResNet 정확도는 90.27%에서 91.17%(102,032건)로, 균등 앙상블은 91.56%(102,474건)에서 92.46%(103,484건)로 바뀌었다. 앙상블의 **순 정답 증가가 1,010건**이라는 산술은 확인된다. 이를 ResNet 단독 또는 신고자만의 정확한 복원 건수로 대체하지 않는다.

기존에 전달된 앙상블 행렬 `[[47734, 6096], [3349, 54740]]`과 수정 후 행렬 `[[47729, 6101], [2334, 55755]]`를 비교하면 TP는 1,015건 증가하고 TN은 5건 감소하여 순 증가가 1,010건이다. 차이의 모든 발화를 NaN 수정 효과로 귀속하려면 동일 sample_id별 수정 전후 확률/예측을 대조해야 한다.

과거 Git 3638dab의 반올림 기록 92.48%와 92.46%는 약 0.02%p 차이다. 과거 발화별 예측 배열이 없어 발화별 1:1 재현은 확인하지 못했으며 근접한 반올림 성적을 완전 재현으로 표현하지 않는다.

### 8.2 CLI 정합성 및 배포 신뢰성 검증
- 독립 실행 제출 CLI(`inference.py`)와 전수 검증 엔진 간의 938건 표본 정합성 대조 결과 **99.15% (930/938건)** 일치율을 확인했다. 8건의 불일치는 결정 임계값(0.500) 직전의 극미세 부동소수점 오차에 기인함을 확인했다.
- 출력 CSV는 UTF-8 BOM 인코딩, 정수 밀리초 시간 규격(`startAt`, `endAt`), 이진 라벨(`speaker` 0 또는 1) 형식을 100% 통과했다.

### 10.1 멘토 피드백 및 개선 방침
- **지적 사항**: 기존 모델 가중치는 Training loss의 역전파로 정상 업데이트되었으나, 최종 에폭 선정 시 공식 Validation Accuracy를 기준으로 best 체크포인트를 저장하는 분기가 존재함. 멘토 피드백에 따라 공식 Validation은 모든 하이퍼파라미터 및 모델 구성을 확정한 후 최종 일반화 성능을 확인하는 용도로만 사용되어야 함.
- **개선 방침**: 사전에 고정한 학습 횟수를 완료한 마지막 가중치를 채택하는 경로 B(`fixed_additional_last`)를 구현하여 학습 중 공식 Validation 평가 및 점수 기반 최고 에폭 선택을 원천 배제함.
- **부모 체크포인트 이력**: 부모 체크포인트(ReDimNet Ep 9, ECAPA Ep 8, ResNet Ep 10)가 과거 `official_validation_best`로 선정되었다는 사실은 보존되며, 신규 실행에서는 점수 기반 선택 분기를 제거하여 사전에 정해진 에폭만을 추가 수행한다.

### 10.2 경로 B 규격 및 전처리 표준화
- **모델별 고정 추가 학습 계획**:
  - ReDimNet2-B2: 부모 에폭 9 가중치 -> 1 에폭 고정 추가 학습 -> 최종 10 에폭 가중치
  - ECAPA-TDNN: 부모 에폭 8 가중치 -> 2 에폭 고정 추가 학습 -> 최종 10 에폭 가중치
  - AudioResNet-50: 기존 10 에폭 완료 가중치 Hash 등록 재사용 (추가 학습 0 에폭)
  - 학습 중 공식 Validation 평가 완전 배제 및 점수 기반 선택 로직 제거
- **전처리 모듈 표준화 (`m2.audio_features`)**:
  - `m2/audio_features.py` 공통 모듈을 통해 Librosa Slaney-scale Mel 스펙트로그램, `top_db=80.0`, `(mel_db + 80.0) / 80.0`, `[0.0, 1.0]` 클립 적용.
  - 학습 데이터셋(`DCCAudioDatasetUnified`), 노트북, 추론 엔진(`Mission2InferenceEngine`) 간 공통 함수 사용. 동일 라이브러리 환경에서 8/16/44.1kHz 합성 WAV의 짧은/긴/무음 발화를 대조하며, 실제 음원의 신규 CLI parity는 Windows에서 별도 확인한다.
- **에폭별 원자적 저장 및 재개(Resume) 지원**:
  - 임시 파일(`.tmp`) 기록 후 원자적 교체(replace)로 체크포인트 무결성 보장.
  - Python, NumPy(전체 5요소 튜플), PyTorch CPU, PyTorch CUDA 전체 RNG 상태 저장·복원; 동일 환경의 CPU 중단·재개 결과를 비교하며 GPU 비트 단위 재현은 별도 확인.
  - 중단 재실행 시 기존 진행 에폭부터 자동 재개, 완료된 실행은 재학습 없이 기존 체크포인트 재사용.
- **동결 설정 및 제출 패키지 무결성 보호**:
  - 미완료(`completed_epoch < planned_epochs`) 체크포인트 및 스모크 체크포인트의 프로덕션 동결 원천 차단.
  - 동결 후 체크포인트 위변조 시 디스크 SHA-256 대조로 export 차단.
