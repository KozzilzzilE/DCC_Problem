# Mission 3 — 임계값 0.5 고정 기준 보정·오심·블렌드 검증

- **평가 지표**: 제출과 같은 **macro F1@0.5** (클래스별 임계값 없음)
- **검증 데이터**: Validation 3,640건, 원본 JSON 에서 `inference.py` 로 재채점
- **환경**: 로컬 RTX 5060 8GB, torch 2.13.0+cu130, transformers 5.15.0, AMP
- **공통 학습 설정**: `klue/roberta-base`, lr 2e-5, 3 epoch, max_length 512, batch 8 × accum 2, `truncate`, 공백 결합 입력
- 이 문서는 집계 통계만 담는다. 원문 transcript 와 표본 식별 정보는 포함하지 않는다.

---

## 1. 요약

| 설정 | macro F1@0.5 | 오심 F1@0.5 |
|---|---:|---:|
| plain BCE (기존 기준선, val_loss 기준 체크포인트) | 0.5967 | 0.032 |
| `--use-pos-weight` (negative/positive, 기존 옵션, val_macro_f1 기준) | 0.6189 | 0.363 |
| **`--use-pos-weight --pos-weight-power 0.5`** | **0.6496** | 0.387 |
| 위 + Training 전용 TF-IDF 블렌드 (w=0.3) | 0.6536 | 0.401 |
| power 0.5 시드 42~45 평균 + TF-IDF 블렌드 | **0.6546** | 0.395 |

1. 제출 점수를 막던 것은 모델 표현력이 아니라 **0.5 고정 임계값에서의 결정점**이었다. 팀이 비교에 쓴 "optimized Macro F1"(0.655) 은 클래스별 임계값을 Validation 에서 고른 값이라 제출에 쓸 수 없고, 실제 제출 점수는 0.600 이었다.
2. 학습 손실의 양성 가중을 `(negative/positive) ** 0.5` 로 주면 9개 클래스가 모두 오르고, 클래스별 임계값을 따로 골라도 더 얻을 것이 없어진다.
3. 발화 경계(`[SEP]`) 입력은 이득이 없었다.
4. 오심은 라벨 관례와 약한 텍스트 신호가 정한 순위 품질 천장(AUROC 약 0.78)에 막혀 있고, 검증된 유일한 개선은 전역 TF-IDF 블렌드다.

## 2. 기준선 재현

| 지표 | 팀 Colab (README) | 로컬 |
|---|---:|---:|
| epoch 2 val loss | 0.2549 | 0.2545 |
| F1@0.5 | 0.6003 | 0.5967 |
| same-set optimized F1 | 0.6554 | 0.6558 |

로컬 결과가 팀 결과와 seed 노이즈 범위에서 일치한다. 공백 결합 입력 CSV(`mission3_train.csv`, `mission3_val.csv`) 는 원본 JSON 을 `m3.labels` 로 다시 만든 것과 본문·라벨이 100% 같다.

기준선에서 클래스별 결정점을 Validation 절반에서 고르고 나머지 절반에서 평가하면(2-fold, 20회) 0.5 대비 **+0.050 (sd 0.004)** 이 오른다. 규정상 쓸 수 없는 방법이지만, 0.5 에서 잃고 있는 양이 이만큼이라는 뜻이다. 그 격차의 71% 가 오심이다 (0.5 에서 F1 0.03).

## 3. pos_weight 거듭제곱

`pos_weight = (negative / positive) ** power` 이고 `negative / positive` 는 **Training 라벨 개수로만** 계산한다. power 는 9개 클래스 공통 스칼라 하나다.

| power | 클래스별 pos_weight (고열 … 호흡곤란) |
|---:|---|
| 1.0 (기존 옵션) | 4.63, 5.54, 9.05, 3.31, 3.61, 7.43, 7.74, 4.50, 6.44 |
| 0.5 | 2.15, 2.35, 3.01, 1.82, 1.90, 2.73, 2.78, 2.12, 2.54 |

| 설정 | macro | 고열 | 구토 | 두통 | 복통 | 어지러움 | 열상 | 오심 | 전신쇠약 | 호흡곤란 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| plain BCE s42 | 0.5967 | 0.687 | 0.588 | 0.518 | 0.815 | 0.645 | 0.882 | 0.032 | 0.546 | 0.660 |
| power 1.0 s42 | 0.6189 | 0.674 | 0.544 | 0.471 | 0.802 | 0.640 | 0.868 | 0.363 | 0.585 | 0.624 |
| **power 0.5 s42** | **0.6496** | 0.689 | 0.590 | 0.555 | 0.819 | 0.659 | 0.884 | 0.387 | 0.590 | 0.673 |

- power 1.0 은 모든 클래스를 과보정한다. 이 모델의 클래스별 Validation 최적 임계값이 0.59~0.83 으로 전부 0.5 위에 있었다.
- power 0.5 는 9개 클래스 모두 기준선보다 높고, 클래스별 결정점 cross-fit 이득이 **−0.0007** 로 사라졌다. 순위 품질(same-set optimized F1 0.6570)은 기준선과 같다.
- power 는 {1.0, 0.5} 중 Validation macro F1@0.5 로 골랐다 (FAQ 3번의 하이퍼파라미터 선택). power 1.0 의 과보정 방향을 보고 0.5 를 정했고, 사전 오프라인 추정에서도 0.5 가 최적이었다.
- 체크포인트 선택 기준은 run 마다 다르다. plain BCE s42 는 팀 기본값인 `val_loss` 최소(epoch 2), power 1.0 s42 와 power 0.5 s42 는 `--checkpoint-metric val_macro_f1`(각각 epoch 3, epoch 2)이다. power 0.5 의 epoch 2 는 val_loss 최소 epoch 와 같으므로 plain BCE 대비 +0.0529 는 val_loss 기준으로 맞춘 비교다. val_macro_f1 기준으로 맞추면 plain BCE 는 epoch 3 의 0.6021 이고 차이는 +0.0475 다. val_loss 기준으로 맞추면 power 1.0 은 epoch 2 의 0.6083 이다.
- power 0.5 의 다른 run(시드 43·44·45, `[SEP]`)도 모두 val_loss 최소 epoch 와 val_macro_f1 최고 epoch 가 같았다.

### 3.1 시드 재현

|---|---:|---:|
| 42 | 0.6496 | 0.387 |

| 44 | 0.6482 | 0.372 |

## 4. 발화 경계 입력 (`[SEP]`)

| 설정 (power 0.5, seed 42) | macro F1@0.5 | 오심 F1@0.5 |
|---|---:|---:|
| 공백 결합 | 0.6496 | 0.387 |
| `[SEP]` 경계 | 0.6464 | 0.382 |

짝 부트스트랩 차이 **−0.0033, 95% CI [−0.008, +0.002]**. 경계는 허용되지만 이득이 없다. 발화의 약 75% 가 이미 문장부호로 끝나 경계가 새로 주는 정보가 적고, `[SEP]` 만큼 입력이 길어져 KLUE 기준 512 토큰 초과가 2.69% → 4.89% 로 는다. `turn` 모드의 `[TURN]` 은 KLUE 토크나이저에 등록돼 있지 않아 여러 조각으로 쪼개지므로 학습에 쓰지 않는다.

## 5. 오심

| 모델 | 오심 F1@0.5 | 임계값 최적 시 최대 F1 | AUROC | AP |
|---|---:|---:|---:|---:|
| plain BCE s42 | 0.032 | 0.398 | 0.777 | 0.324 |
| power 1.0 s42 | 0.363 | 0.405 | 0.778 | 0.319 |
| power 0.5 s42 | 0.387 | 0.412 | 0.779 | 0.320 |
| power 0.5 4-seed + TF-IDF | 0.395 | — | 0.781 | 0.334 |

- power 0.5 에서 오심 결정점은 이미 거의 최적이다. 남은 제약은 순위 품질이고, 손실 가중·시드·경계·(팀 Colab 의) 백본 4종이 모두 같은 천장에 머문다.
- 오심은 단독으로 나오는 경우가 7.2% 뿐이고, 오심 양성 통화의 평균 라벨 수가 2.49 개(전체 1.43 개)다. P(오심 | 구토) 0.289, P(오심 | 어지러움) 0.257 로 동반 증상 성격이 강하다.
- 명시적 오심 표현(메스껍다·울렁·토할 것 같다·속이 안 좋다 등)은 오심 양성의 약 14% 에만 있고, 그런 표현이 있는 통화도 약 절반만 오심으로 라벨돼 있다(나머지는 구토·어지러움 등).
- Training 에서만 만든 CPU proxy 로 하드 네거티브 가중(오심=0 & 구토=1), 오심 label smoothing, 다른 증상 로짓을 조건으로 쓰는 헤드, 오심 전용 모델을 확인했고 모두 순위 품질을 올리지 못했다. 오심만 따로 임계값·가중을 바꾸는 방법은 클래스별 임계값 조정과 같아 쓰지 않는다.

## 6. Training 전용 TF-IDF 블렌드

`m3/tfidf_member.py`: char_wb 2-4gram + 공백 토큰 1-2gram TF-IDF, 클래스별 LogisticRegression(`C=0.15`, `class_weight='balanced'`). **Training CSV 로만 적합**하고 Validation/Test 는 transform 만 한다. 트랜스포머 확률과 **9개 클래스 공통 가중치 하나(w=0.3)** 로 섞고 0.5 로 판정한다.

| 기준 모델 | macro F1@0.5 | 오심 F1@0.5 | 오심 AP |
|---|---|---|---|
| seed 42 | 0.6496 → 0.6536 | 0.387 → 0.401 | 0.320 → 0.335 |
| seed 43 | 0.6453 → 0.6497 | 0.381 → 0.395 | 0.305 → 0.320 |
| seed 44 | 0.6482 → 0.6522 | 0.372 → 0.393 | 0.327 → 0.335 |
| seed 45 | 0.6470 → 0.6497 | 0.392 → 0.395 | 0.330 → 0.336 |
| 4-seed 평균 | 0.6523 → 0.6546 | 0.390 → 0.395 | 0.324 → 0.334 |

- 단일 모델에서는 매번 오르고 다른 클래스 손실은 최대 0.004 다. seed 42 기준 짝 부트스트랩 macro 차이 95% CI [+0.001, +0.008].
- 4-seed 평균 위에서는 이득이 줄고 CI 가 0 을 포함한다 (macro [−0.001, +0.006]).
- 이득의 대부분은 balanced LR 이 확률을 끌어올려 작동점이 옮겨지는 효과다. 가중치는 전 클래스 공통이라 클래스별 임계값 조정에 해당하지 않는다.
- **하이퍼파라미터 선택 경위.** C=0.15 는 처음에 Validation 오심 지표를 보며 탐색했고, 이후 Training 5-fold OOF 에서 오심 AUROC/AP 가 가장 높은 값으로 확인했다 (OOF macro 기준으로는 C=0.5 가 약간 높았다). w 는 {0~0.6} 중 seed 42·43 run 의 Validation macro F1@0.5 로 골랐다. 둘 다 9개 클래스 공통 스칼라이며 FAQ 3번이 허용한 하이퍼파라미터 선택이지만, seed 42·43 행의 개선폭은 선택에 쓴 데이터에서 잰 값이라 낙관적이다. w 를 정한 뒤 학습한 seed 44·45 에서는 macro +0.0040, +0.0027 이었다.

| 번들 | macro F1@0.5 | 오심 F1 | Validation 추론 시간 |

`runs/` 는 git 에 올라가지 않는다. 번들은 `ensemble.json` 과 그것이 가리키는 멤버 `best_model` 폴더·TF-IDF 파일을 **한 폴더 안에** 담는다. 제출은 `--ckpt_path` 폴더 하나이므로, 폴더 밖을 가리키는 번들은 로컬에서는 돌아도 제출하면 깨진다 (추론 시 경고). 위 두 번들은 자기완결 구조로 다시 만들어, 번들 폴더만 다른 위치로 복사해 실행해도 같은 점수가 나오는 것을 확인했다. 형식은 README 의 "권장 레시피" 절을 따른다.

## 8. 하지 않은 것과 이유

| 방법 | 이유 |
|---|---|
| Validation 최적 임계값에 맞춘 클래스별 pos_weight | 클래스별 임계값 튜닝을 손실로 옮긴 것과 같다 |
| 사후 bias·임계값, 클래스별 앙상블 가중·라우팅 | 0.5 고정 규정과 충돌 |
| 모든 확률이 0.5 미만일 때 최고 1개 강제 출력 | 사후 결정 규칙이고, 출제 문서상 증상 0개 통화도 있을 수 있다 |
| klue/roberta-large, 백본 혼합 앙상블 | 보정 후 기대 이득이 seed 노이즈 수준이고 비용이 크다 |
| Validation 본문으로 MLM·재학습, TF-IDF 를 train+val 로 재적합 | Validation 을 학습에 쓰는 것 (실격 사유) |
