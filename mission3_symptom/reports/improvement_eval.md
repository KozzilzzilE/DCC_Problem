# Mission 3 개선 실험: 백본·TAPT·LLRD (2026-09-28 ~ 09-29)

> 모든 수치는 로컬 Validation 3,640건의 **macro F1@0.5 (임계값 0.5 고정)** 다. 학습(역전파)은 Training 29,200건만 썼다. Validation 은 체크포인트 선택(`--checkpoint-metric val_macro_f1`), 레시피·하이퍼파라미터 선택, 평가, 오류 분석에 썼다(FAQ 허용 범위). 공통 레시피는 `calibration_eval.md` 의 권장 설정(KLUE-RoBERTa-base, `--use-pos-weight --pos-weight-power 0.5`, 3 epoch, 유효 배치 16, AMP)이다.

## 2. 평가 방법

- **짝 비교:** 같은 시드끼리 원본과 비교했다(같은 헤드 초기화·데이터 순서). CI 는 Validation 행을 1,000회 재추출한 시드 평균 차이의 95% 구간이다. 시드 간 분산은 반영하지 않는다.
- **앙상블 비교:** 균등 평균 + TF-IDF(w=0.3) 다. 합동 부트스트랩은 시드를 복원추출(4개 뽑으면 서로 다른 시드는 평균 약 2.7개)하고 행도 함께 재추출한다. 표의 첫 값은 **부트스트랩 평균**이고, 관측 차이와 다를 수 있다. "차이>0 비율"은 부트스트랩 표본 중 차이가 양수인 비율이다.
- **해석할 때 주의할 점:**
  - 단일 시드 macro F1 의 표준편차는 약 0.002 다.
  - 모든 설정이 같은 원본 시드를 기준으로 하므로 "짝 방향" 패턴이 설정 간에 상관된다. 원본 시드 43(0.6453)이 가장 낮아서 거의 모든 설정이 시드 43 에서 + 다.
  - 9개 설정을 한 기준과 비교했으므로 가장 좋은 설정의 수치에는 선택 편향이 있다.
  - TF-IDF 의 C=0.15·w=0.3 은 원본 멤버로 Validation 에서 고른 값이다. 번들 절대값은 낙관적이고, 비교는 원본 쪽에 약간 유리하다.

## 4. 항목별 결론

### ① 이종 백본 앙상블 — 단일 시드로는 이득 확인 안 됨
KF-DeBERTa 와 KLUE s42 의 예측 상관(클래스별 Pearson 평균)은 0.971 로 KLUE 시드끼리(0.969)와 같다. 같은 모델 수로 맞추면 KLUE 3개 + DeBERTa 는 KLUE 4개보다 +0.0006(부분집합 최대 +0.0011)이고 KoELECTRA 를 섞으면 0 이하였다. 각 백본은 시드 하나, 튜닝 없이 돌린 결과다.

### ② RoBERTa-large — 단일 시드로는 F1@0.5 에서 KLUE-base 와 구분 안 됨
- large 와 DeBERTa 는 AUROC 를 원본 s42 대비 +0.0037 올렸다. 그 대부분은 FPR 10% 초과 구간에서 나왔고, 0.5 작동점(FPR 약 6%) 근처 면적은 +0.0004 다.
- 다만 FPR 폭당으로는 작동점 근처 이득이 더 크다. AP 로는 DeBERTa(0.6903)가 채택한 여러 레시피보다 높은데도 F1@0.5 는 오르지 않았다.
- AUROC 도 AP 도 F1@0.5 순위를 보장하지 않으므로, 모델 선택은 F1@0.5 를 직접 봐야 한다.

### ③ pos_weight power 미세 탐색 — 학습 없이 기각 (분석용 시뮬레이션)
pos_weight 를 바꾸면 최적해에서 로짓이 `Δpower × log(neg/pos)` 만큼 이동한다. 저장된 로짓으로 이 이동을 흉내 내면 실제 power 1.0·plain BCE run 과 0.004 이내로 맞는다. 4시드 평균은 0.45 → 0.6465, 0.50 → 0.6475, 0.55 → 0.6473, 0.60 → 0.6472 로 평평하다. 이 시뮬레이션은 제출 경로와 무관한 분석이다.

### ④ 미세조정 기법 — LLRD 채택, 나머지 제외
- **LLRD:** 채택. 5절 참고.
  - 0.9·3e-5 → 0.8·5e-5 는 AP 와 최소 val 손실이 네 시드 모두 개선됐다. 이 단계는 최상위 학습률도 함께 바뀌어서 감쇠만의 비교는 아니다.
  - 0.8 → 0.7 은 방향이 섞여서 0.8 로 정했다.
- **Label smoothing:** 이전 오심 실험(CPU 프록시)에서 효과가 없어 제외했다.
- **Cosine 스케줄러:** 기대 이득 대비 GPU 시간이 커서 제외했다.
- **상위 층 재초기화, 헤드 LR 배수, 임베딩 동결, warmup 변경:** 문헌(Zhang et al. 2021, Sun et al. 2019)상 이 데이터 크기(29k)에서 이득이 작아 제외했다.

### ⑤ TF-IDF 멤버 고도화 — 효과 없음
- word 1-3gram, char 2-5gram 변형은 블렌드 결과가 ±0.0003 이다.
- LightGBM 은 단독 점수는 높다(0.6091 vs LR 0.5890). 그러나 트랜스포머와 더 비슷하게 틀려서(상관 0.856 vs 0.824) 블렌드가 오히려 떨어졌다(4시드 0.6528 vs 0.6546).
- 기존 LR 멤버(C=0.15, w=0.3)를 유지한다.

### 추가: TAPT (task-adaptive pretraining)
KLUE-RoBERTa 원본의 MLM 손실은 이 통화 전사문에서 5.13(Training 256건) / 5.04(Validation 256건)였다. 도메인 차이가 크다는 뜻이다. Training CSV 의 text 만으로 MLM(15% 마스킹, lr 5e-5, 6% warmup + 선형 감쇠, 항상 마지막 epoch 저장)을 이어 학습한 뒤, 같은 레시피로 분류 학습했다.

| TAPT 길이 | 본 텍스트 MLM 손실 (Training 256건) | 안 본 텍스트 MLM 손실 (Validation 256건, 평가 전용) | 분류 F1 (시드 42~44 평균) |
|---|---:|---:|---:|
| 없음 | 5.127 | 5.043 | 0.6477 |
| 10ep | 0.948 | 1.001 | 0.6515 |
| 20ep | 0.865 | 0.963 | 0.6527 |

- 표의 MLM 손실은 `tapt_mlm.py --eval-csv` 가 같은 표본·마스크(표본 random_state 2024, 마스크 seed 2024, GPU fp16)로 잰 값이다. 원본에서도 두 표본 사이에 약 −0.08 의 차이가 있으므로, 본/안 본 차이의 증가분(원본 −0.08 → 10ep +0.05 → 20ep +0.10)을 암기 증가의 신호로 본다.
- 4ep run 은 이 옵션을 넣기 전에 학습해서 다른 표본·마스크(표본 random_state 0, 마스크 seed 123, CPU fp32)로 따로 쟀다: 1.024 / 1.072. 위 표와 절대값을 직접 비교하지 않는다.
- 분류 F1 짝 비교:
  - 4ep → 20ep: +0.0036 [+0.0004, +0.0064] (시드 42~44)
  - 10ep → 20ep: +0.0006 [−0.0022, +0.0033] (시드 42~45). 시드 42~44 는 상승, 시드 45 는 F1 −0.0010, AP −0.0001 이다.
- 원 논문(Gururangan et al. 2020)은 TAPT 를 100 epoch 돌렸지만 길이 ablation 은 없다. 10→20ep 이득이 구분되지 않고 암기 신호가 커져서, 40ep 이상(약 6시간)은 시도하지 않았다. 이 판단에 Validation MLM 손실 추세를 참고했다(하이퍼파라미터 선택, FAQ 허용).
- TAPT 길이마다 TAPT run 이 하나뿐이라, TAPT 자체의 run 간 분산은 반영되지 않았다.
- **조합 효과:**
  - TAPT 4ep + LLRD 0.9 는 가산되지 않았다(+0.0007).
  - TAPT 20ep + LLRD 0.8 은 부분적으로 가산됐다. 두 단독 이득의 합은 +0.0085, 조합은 +0.0068 이다. 조합은 TAPT 20ep 단독보다 +0.0027 [−0.0008, +0.0061], LLRD 0.8 단독보다 +0.0024 [−0.0019, +0.0067] 높다(각각 CI 가 0 을 포함).

## 5. LLRD 효과의 원인 분리 (감쇠 0.9·lr 3e-5 기준)

LLRD 0.9 실험은 층별 감쇠와 최상위 학습률 상향(2e-5 → 3e-5)을 동시에 바꿨다. 학습률만 3e-5 로 올린 대조군을 같은 시드로 돌렸다.

| 시드 | 원본 (2e-5) | lr 3e-5 만 | LLRD 0.9 (3e-5) | 최소 val 손실 (원본 / 3e-5 / LLRD) | epoch 3 train 손실 (원본 / 3e-5 / LLRD) |
|---|---:|---:|---:|---|---|
| 42 | 0.6496 | 0.6485 | 0.6533 | 0.4260 / 0.4252 / 0.4233 | 0.3776 / 0.3731 / 0.3832 |
| 43 | 0.6453 | 0.6465 | 0.6482 | 0.4267 / 0.4268 / 0.4242 | 0.3780 / 0.3720 / 0.3841 |
| 44 | 0.6482 | 0.6461 | 0.6509 | 0.4291 / 0.4296 / 0.4288 | 0.3779 / 0.3726 / 0.3834 |

- **학습률만 올리면 원본과 같다.** F1 −0.0007, AP −0.0004 다.
- **같은 학습률에서 감쇠를 켜면 오른다.** F1 +0.0038 [+0.0004, +0.0073], AP +0.0033 이고, 세 시드 모두 상승한다.
- **감쇠 쪽이 train 손실은 높고 최소 val 손실은 낮다.** 아래층 표현을 덜 흔드는 규제로 해석한다. 다만 아래층 평균 학습률이 낮아진 효과와 구분되지는 않는다.
- **작동점 이동 효과는 거의 없다.** 클래스별로 예측 양성 수를 맞춰 비교해도 +0.0031 중 +0.0026~0.0030 이 남는다.
- **권장 설정(0.8·5e-5)에는 같은 학습률의 대조군이 없다.** 따라서 "학습률 상향이 아니라 감쇠"라는 결론은 0.9·3e-5 에 대한 것이다.

## 6. 남은 오류의 성격 (분석용)

19개 모델(트랜스포머 17: KLUE 계열 14 + 다른 백본 3, TF-IDF LR·LightGBM)의 Validation 예측으로 분석했다. 분석 스크립트는 저장소 밖 작업 폴더에 있다.

- **공통 오류:** 클래스별 최고 단일 모델 오류의 **49.8%** 를 19개 모델이 모두 틀린다. 새 번들 오류의 48.9% 도 같은 칸이다. 다만 모델이 사실상 두 계열(트랜스포머, TF-IDF)이라, 이는 "이 모델 계열로는 풀리지 않는 행"이라는 뜻이다. 라벨이 틀렸다는 증거는 아니다.
- **주호소 위주 라벨 관례:** 같은 증상 표현이라도 통화에서 처음 언급되면 양성 비율이 훨씬 높다.

  | 증상 | 처음 언급 시 양성 비율 | 나중에 언급 시 양성 비율 |
  |---|---:|---:|
  | 고열 | 0.72 | 0.19 |
  | 복통 | 0.92 | 0.55 |
  | 호흡곤란 | 0.46 | 0.15 |

  모델은 이 관례를 이미 학습했다.
- **통화 밖 정보로 추정되는 라벨:** 모든 모델이 놓친 양성의 81~100% 는 해당 증상 표현이 없다. Training 에서 가장 비슷한 통화들(char TF-IDF kNN)의 양성 비율도 음성 수준이다. 이 두 검사는 모델이 쓰는 것과 같은 어휘 단서를 보므로 부분적으로 순환적이다.
- **다른 레버 (모두 분석용이며, 제출에는 쓸 수 없다):**
  - 클래스별 임계값을 절반에서 고르고 나머지 절반에서 평가하면 −0.002 다. 규정상 쓸 수 없고, 0.5 가 이미 최적임을 확인하는 용도다.
  - Validation 5-fold 스태커(다른 클래스 로짓·키워드 위치), "라벨 1개 이상" 강제도 이득이 없었다.
- **데이터 양:** TF-IDF 학습 곡선에서 Training 을 두 배로 늘릴 때마다 AUROC 가 약 +0.005 오른다. 오심만 거의 평평하다. 규정상 제공 데이터만 쓸 수 있다.
- **나머지 오류:** 약 절반은 임계값 부근에서 시드마다 뒤집히는 행으로, 앙상블이 일부 회수한다.
- **표본 점검:** 오류 표본 60건(오심·두통·전신쇠약, 모든 모델이 틀린 행)은 Claude 가 오프라인 분석 보조로 읽고 분류했다. 모델·추론 경로와는 무관하다. 한 명이 판정했고 표본도 작다(라벨 불일치 추정 48%, 95% CI 약 35~61%). 방향 참고용이다.

## 7. 제출 번들과 재현

```text
runs/submit_tapt20_llrd08_4seed_tfidf/   (1.7GB, 자기완결)
├── ensemble.json          # members ./seed42~45, tfidf_weight 0.3
├── seed42 ~ seed45/       # 각 run 의 best_model 복사본
└── tfidf/tfidf_lr.joblib  # 기존 Training 전용 TF-IDF LR (C=0.15, runs/tfidf_lr_c0.15)
```

아래 명령은 모두 `mission3_symptom/` 에서 실행한다.

```bash
# 1) TAPT: 역전파는 Training CSV 의 text 만. --eval-csv 는 진단용 손실 기록(no_grad)이고 생략해도 된다. RTX 5060 에서 약 2시간 35분
python tapt_mlm.py --train-csv <mission3_train.csv> --eval-csv <mission3_val.csv> --output-dir runs/tapt_klue_base_e20 --local-files-only --amp --epochs 20
```

```bash
# 2) 분류 학습: 시드 42~45 각각 (시드당 약 20분)
python train.py --train-csv <mission3_train.csv> --val-csv <mission3_val.csv> --model-name-or-path runs/tapt_klue_base_e20 --local-files-only --learning-rate 5e-5 --llrd-decay 0.8 --use-pos-weight --pos-weight-power 0.5 --checkpoint-metric val_macro_f1 --amp --seed 42 --output-dir runs/klue_tapt_e20_llrd0.8_lr5e-5_posw0.5_seed42
```

```bash
# 3) 번들 구성: 멤버 best_model 과 TF-IDF 멤버를 한 폴더로 복사
B=runs/submit_tapt20_llrd08_4seed_tfidf; mkdir -p $B/tfidf
for s in 42 43 44 45; do cp -r runs/klue_tapt_e20_llrd0.8_lr5e-5_posw0.5_seed$s/best_model $B/seed$s; done
cp runs/tfidf_lr_c0.15/tfidf_lr.joblib runs/tfidf_lr_c0.15/tfidf_lr.json $B/tfidf/
# ensemble.json 은 위 트리처럼 작성 (형식은 README "임계값 0.5 고정 기준 권장 레시피" 절). TF-IDF 멤버 학습은 train_tfidf_member.py
```

```bash
# 4) 제출 추론 (번들 폴더만 있으면 된다)
python inference.py --label_dir <json 폴더> --ckpt_path runs/submit_tapt20_llrd08_4seed_tfidf --output ./outputs/mission3.csv
```

- **재현 차이:** `runs/tapt_klue_base_e10`, `e20` 은 `--eval-csv` 의 마스크 생성이 CUDA 난수를 다시 시드하던 수정 전 코드로 만들어졌다. 그래서 dropout 난수열이 seed 2024 로 바뀌었다. Validation 내용이 가중치에 들어간 것은 아니다. 지금 코드(`build_eval_batches`, fork_rng 격리)로 다시 학습하면 옵션 유무와 관계없이 같은 난수열을 쓰지만, 기존 산출물과 비트 단위로 같지는 않다.
- **검증:** 번들을 저장소 밖으로 복사해 원본 Validation JSON 3,640건에서 추론했다.
  - 정답과 대조한 결과 **0.6593** 이 재현됐다. 저장된 확률로 만든 예측과 3,640×9 칸이 모두 같다.
  - 증상 0개 예측은 71건이다. 추론 시간은 fp32 약 104초(통화당 28.7ms), `"precision": "fp16"` 번들 42초(통화당 11.5ms)이고 두 결과의 제출 행은 같다.
- **증상별 변화 (번들 vs 현재 번들):**

  | 증상 | 오심 | 열상 | 전신쇠약 | 복통 | 어지러움 | 구토 | 호흡곤란 | 고열 | 두통 |
  |---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
  | 변화 | +0.020 | +0.012 | +0.008 | +0.003 | +0.003 | 0.000 | 0.000 | −0.002 | −0.002 |

  macro 이득 +0.0046 의 약 절반이 오심이다.
- **대안:** 12개 모델(이 레시피 4 + LLRD 0.8 4 + TAPT 20ep 4)은 0.6599 로 +0.0007 이다. 잡음 범위이고 추론 시간이 약 3배라 채택하지 않았다.

## 8. 규정 준수

- **임계값:** 모든 클래스 0.5 고정이다. 번들 검증 규칙(클래스별 값·`threshold` 키 거부)은 그대로다.
- **TAPT:**
  - 역전파에는 Training CSV 의 text 만 썼고, 라벨은 읽지 않았다.
  - `--eval-csv` 로 Validation 256건의 MLM 손실을 epoch 마다 기록했다. 평가 모드·no_grad 이고 가중치에 영향이 없다. 체크포인트는 항상 마지막 epoch 이다.
  - 이 손실 추세는 TAPT 길이를 더 늘리지 않는 판단에 참고했다(하이퍼파라미터 선택).
  - `tapt_klue_base_e10/e20/tapt_config.json` 의 `source` 문구("Validation unused")는 이 옵션을 반영하기 전의 문구다. 지금 코드는 eval_csv 사용을 기록한다.
- **Validation 사용:** 역전파에는 쓰지 않았다. 체크포인트·레시피·하이퍼파라미터 선택과 평가, 분석에만 썼다.
- **외부 자원:** 공개 사전학습 모델(klue/roberta-base 등)만 썼고, 모델·추론 경로에 상용 API 는 없다.

## 9. 한계

- 모든 결정과 평가가 같은 Validation 3,640건에서 이뤄졌다. 레시피 선택 자체가 낙관적 편향을 만든다. 번들 수준 개선(관측 +0.0046)은 두 부트스트랩 CI 모두 0 을 포함한다.
- 다른 백본은 시드 하나에 튜닝도 하지 않았다.
- TAPT 길이 비교는 길이마다 TAPT run 이 하나뿐이다.
- 오류 성격 분석은 같은 라벨로 학습한 두 계열 모델의 합의에 기댄다. 따라서 라벨 오류, 통화 밖 정보, 드문 암시적 표현을 구분하지 못한다.
