## 최종 학습과 번들

- **학습:** Training 전체 29,200건을 썼다. TAPT 가중치에서 시작했고 lr 5e-5, LLRD 0.8, p=0.5 다.
  - 3 epoch 스케줄의 2 epoch 시점에서 저장했다 (`--checkpoint-metric fixed_epoch --checkpoint-epoch 2`).
  - seed 42·43·44·45 를 각각 13분 정도 학습했다.
  - 진행 기록에 찍힌 dev 점수(0.69 안팎)는 학습 데이터 안의 행이라 의미가 없고, 아무 결정에도 쓰지 않았다.
- **번들:** `runs/devsel/bundle/`, 크기 1.77 GB.
  - 멤버 4개, TF-IDF 없음.
  - 가중치는 fp32 로 저장돼 있다. `ensemble.json` 의 `"precision": "fp16"` 은 CUDA 추론 때 fp16 autocast 를 켜는 설정이다.
  - 파라미터 442,500,132 (110,625,033 × 4).

> **덧붙임 (10-02):** 이 문서는 10-01 실행 기록이라 그대로 둔다. 10-01 Validation 확인은 위 폴더 번들(`runs/devsel/bundle/`, `ensemble.json`)로 했다. 이후 같은 가중치 4개를 바꾸지 않고 `.pt` 파일 하나(`runs/devsel/mission3.pt`, 제출본의 `ckpt/mission3.pt`)로 옮겼다. 이 `.pt` 로 Validation 을 다시 추론한 예측은 첫 확인과 3,640행 모두 같았다. `.pt` 로 잰 전체 실행 시간은 약 43초(10-02 여러 번 실측 42.7~45.1초, 샘플당 약 12 ms)다.

## 사전 등록 문서 보충 (문서는 등록 시점 그대로 둔다)

- **"make_csv.py 로 원본 JSON 에서 다시 만들 수 있다":** 행·순서·라벨은 같다. 다만 본문 1행(651e4b6d304f68a2e7021acf_20220503)의 공백이 달라 파일 sha256 는 split.json 기록과 다르다. 분할은 행 번호로 정해지므로 같은 통화가 같은 쪽으로 간다.
- **"devsel.py 는 모든 run 의 run_config.json 을 확인한다":** 정확히는 선택에 쓰는 run 만 확인한다 (p 후보 3개, 레시피 후보 4개).
  - 최종 학습 run 은 Training 전체로 학습하므로 이 확인 대상이 아니다.
  - 최종 학습에 Validation 이 들어가지 않는 것은 `run_dev_selection.sh` 가 평가 CSV 로 dev 분할만 넘기기 때문이다.
- **"번들 … fp16":** 가중치를 fp16 으로 바꾼다는 뜻이 아니다. 추론 정밀도 설정(`"precision": "fp16"`)이다.
